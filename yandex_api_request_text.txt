=== ЗАЯВКА НА ДОСТУП К API ЯНДЕКС ДИРЕКТА (дополненная) ===

Приложение: AI StroiApp Manager
Назначение: Автоматическое создание и управление рекламными кампаниями интернет-магазина строительных материалов stroiapp.ru

---

ОПИСАНИЕ РАБОТЫ ПРИЛОЖЕНИЯ

Приложение интегрируется с API Яндекс Директа исключительно для управления собственными рекламными кампаниями магазина stroiapp.ru. Программа не осуществляет подбор ключевых слов, не анализирует ставки конкурентов и не использует сторонние данные.

Рабочий процесс:
1. Менеджер магазина выбирает товары из собственного каталога (база данных OpenCart).
2. Приложение генерирует текст объявления на основе названия товара, цены и наличия (без использования внешних сервисов).
3. По нажатию кнопки «Создать кампанию» программа последовательно создаёт: кампанию → группу объявлений → объявление → ключевые слова (названия товаров используются как ключевые слова).
4. Менеджер просматривает созданную кампанию в личном кабинете Директа и запускает показы.
5. Приложение периодически проверяет статус кампании (активна/остановлена/на модерации) и уведомляет менеджера об окончании бюджета или отклонении объявлений.

1. НАЗВАНИЯ МЕТОДОВ API ДИРЕКТА (с конкретными параметрами)

Используются методы API v5 (JSON) через HTTPS с Bearer-авторизацией.

Сервис Campaigns (управление кампаниями):
  • Campaigns.get — получение списка кампаний аккаунта. Параметры запроса: SelectionCriteria (Id, Types: ["TEXT_CAMPAIGN"]), FieldNames: ["Id", "Name", "Status", "State", "Type", "DailyBudget"], TextCampaignFieldNames: ["BiddingStrategy"]. Используется для проверки статуса и остатка бюджета.
  • Campaigns.add — создание текстовой кампании. Параметры: Name (≤255 симв), StartDate (текущая дата), DailyBudget (Amount, Mode: "STANDARD"), TextCampaign: {BiddingStrategy: {Search: {BiddingStrategyType: "HIGHEST_POSITION"}, Network: {BiddingStrategyType: "NETWORK_DEFAULT"}}, Settings: {Key: "GEO", Value: "1"} (Москва), NegativeKeywords: {Key: " NegativeKeywords", Value: []}. Тип кампании: "TEXT_CAMPAIGN".
  • Campaigns.update — изменение параметров кампании (бюджет, название). Параметры: Id, DailyBudget.
  • Campaigns.suspend — остановка кампании (по запросу менеджера). Параметр: SelectionCriteria {Ids: […]}.
  • Campaigns.resume — возобновление показов. Параметр: SelectionCriteria {Ids: […]}.
  • Campaigns.archive — архивирование завершённой кампании. Параметр: SelectionCriteria {Ids: […]}.

Сервис AdGroups (группы объявлений):
  • AdGroups.add — создание группы объявлений в кампании. Параметры: CampaignId (ID созданной кампании), Name (≤255 симв, шаблон: «Группа — {название товара}»), RegionIds: [1] (Москва), NegativeKeywords: [] (пустой массив, без минус-слов).
  • AdGroups.get — получение списка групп кампании. Параметры: SelectionCriteria {CampaignIds: […]}, FieldNames: ["Id", "Name", "Status"].

Сервис Ads (объявления):
  • Ads.add — создание текстового объявления. Параметры: AdGroupId (ID группы), TextAd: {Title (≤33 симв, генерируется из названия товара), Title2 (≤30 симв, необязательное), Text (≤75 симв, генерируется из описания товара), Href (URL карточки товара на stroiapp.ru), Mobile ("false")}. Всего создаётся 1 объявление на группу.
  • Ads.get — получение статуса объявления. Параметры: SelectionCriteria {AdGroupIds: […]}, FieldNames: ["Id", "Status", "State", "Type"], TextAdFieldNames: ["Title", "Text", "Href"].
  • Ads.update — обновление текста объявления (при изменении цены товара). Параметры: Id, TextAd: {Title, Text, Href}.
  • Ads.delete — удаление объявления (при удалении товара из магазина). Параметр: SelectionCriteria {Ids: […]}.

Сервис Keywords (ключевые слова):
  • Keywords.add — добавление ключевых слов в группу. Параметры: AdGroupId (ID группы), Keywords: [{Keyword (≤4096 симв, используется название товара как ключевое слово, без использования сторонних сервисов подбора), UserParam1 (≤25 симв, необязательно), UserParam2 (≤25 симв, необязательно)}]. За один вызов добавляется 1–10 ключевых слов (не более 50 на группу). Ставка не устанавливается через keywords.add, используется стратегия кампании.
  • Keywords.get — получение статуса ключевых слов. Параметры: SelectionCriteria {AdGroupIds: […]}, FieldNames: ["Id", "Keyword", "Status", "State", "ServingStatus"].
  • Keywords.delete — удаление ключевых слов (при удалении товара). Параметр: SelectionCriteria {Ids: […]}.

Сервис Bids (управление ставками):
  • Bids.get — получение текущих ставок по ключевым словам. Параметры: SelectionCriteria {KeywordIds: […]}, FieldNames: ["KeywordId", "Bid", "AuctionBids"]. Используется исключительно для отображения менеджеру текущей ставки, без анализа конкурентов.
  • Bids.set — установка ставки вручную менеджером. Параметры: Bids: [{KeywordId, Bid (в микроединицах)}]. Вызывается только по явному запросу менеджера (0–2 раза в неделю).

Сервис Reports (отчёты):
  • Reports.get — получение статуса сформированного отчёта. Параметры: SelectionCriteria (ReportName), FieldNames: ["ReportName", "Status", "Url"].
  • Reports.add — создание отчёта по кампании. Параметры: ReportName, DateRangeType ("CUSTOM_DATE_RANGE", DateFrom, DateTo), Format: "TSV", IncludeVAT: "YES", Columns: ["CampaignName", "Clicks", "Impressions", "Cost", "Ctr"]. Отчёт формируется 1 раз в сутки.

2. СХЕМА И ПОСЛЕДОВАТЕЛЬНОСТЬ ВЫЗОВА МЕТОДОВ (подробная)

A. Авторизация и проверка аккаунта (каждый запрос):
   1. Формируется HTTP-заголовок Authorization: Bearer {токен}
   2. Проверяется наличие токена в конфигурации приложения
   3. При отсутствии токена — запрос не выполняется, возвращается ошибка клиенту

B. Проверка статуса кампаний (при открытии раздела «Реклама» в панели управления):
   1. Campaigns.get (SelectionCriteria: {Types: ["TEXT_CAMPAIGN"]}, FieldNames: ["Id", "Name", "Status", "State", "DailyBudget"])
   2. Если кампаний > 0 → AdGroups.get (CampaignIds: […]) для получения групп
   3. Если групп > 0 → Ads.get (AdGroupIds: […]) для получения статуса объявлений
   4. Если объявлений > 0 → Keywords.get (AdGroupIds: […]) для проверки статуса ключевых слов
   5. Если DailyBudget接近 0 → уведомление менеджеру
   Последовательность: 1→2→3→4 (синхронная цепочка, каждый следующий зависит от результатов предыдущего)

C. Создание рекламной кампании (по нажатию кнопки «Создать кампанию»):
   1. Campaigns.add (Name, StartDate, DailyBudget, TextCampaign: {BiddingStrategy: {Search: "HIGHEST_POSITION", Network: "NETWORK_DEFAULT"}, Settings: {GEO: 1}})
   2. Из ответа извлекается CampaignId (AddResults[0].Id)
   3. AdGroups.add (CampaignId, Name, RegionIds: [1])
   4. Из ответа извлекается AdGroupId
   5. Ads.add (AdGroupId, TextAd: {Title, Text, Href})
   6. Из ответа извлекается AdId
   7. Keywords.add (AdGroupId, Keywords: [{Keyword: название товара}])
   8. Из ответа извлекаются KeywordIds
   9. Campaigns.get (Id = CampaignId) — финальная проверка статуса
   Последовательность: 1→2→3→4→5→6→7→8→9 (строго синхронная, каждый шаг зависит от ID предыдущего)

D. Обновление кампании (при изменении цены товара в магазине):
   1. Campaigns.get (SelectionCriteria: {Ids: [CampaignId]})
   2. Если статус «Активна» → Ads.get (AdGroupIds: [AdGroupId])
   3. Ads.update (Id = AdId, TextAd: {Title: новое название + цена, Text, Href})
   Последовательность: 1→2→3

E. Остановка/возобновление кампании (по запросу менеджера):
   1. Campaigns.suspend (SelectionCriteria: {Ids: [CampaignId]}) или Campaigns.resume (SelectionCriteria: {Ids: [CampaignId]})
   2. Campaigns.get (SelectionCriteria: {Ids: [CampaignId]}) — проверка нового статуса
   Последовательность: 1→2

F. Архивирование завершённой кампании:
   1. Campaigns.archive (SelectionCriteria: {Ids: [CampaignId]})
   2. Campaigns.get (SelectionCriteria: {Ids: [CampaignId]}) — проверка статуса
   Последовательность: 1→2

G. Мониторинг по расписанию (автоматически, раз в 4 часа):
   1. Campaigns.get (SelectionCriteria: {Types: ["TEXT_CAMPAIGN"]}, FieldNames: ["Id", "Name", "Status", "State", "DailyBudget"])
   2. Если обнаружены кампании со статусом «ENDED» или бюджетом = 0 → уведомление в Telegram
   3. Если кампания на модерации более 24 часов → Keywords.get (AdGroupIds: […]) для проверки причины
   Последовательность: 1→(2 или 3 по условию)

H. Формирование ежедневного отчёта (автоматически, в 03:00 ночи):
   1. Reports.add (ReportName: "daily_report_YYYYMMDD", DateRangeType: "CUSTOM_DATE_RANGE", DateFrom: вчера, DateTo: вчера)
   2. Цикл ожидания: Reports.get (ReportName) каждые 60 секунд, пока Status != "DONE"
   3. При Status = "DONE" → скачивание по Url, парсинг TSV, сохранение в базу
   4. При Status = "CANCELLED" → логирование ошибки, повторная попытка через 1 час (макс. 3 попытки)
   Последовательность: 1→2→3 или 1→2→4→повтор 1

4. ОБРАБОТКА ОШИБОК (детальная)

Общая архитектура обработки ошибок:
• Каждый вызов API обёрнут в try-except блок
• Все HTTP-запросы выполняются с таймаутом 60 секунд (connect timeout: 10 сек, read timeout: 60 сек)
• При получении HTTP-статуса ≠ 200 — анализируется тело ответа

Конкретные сценарии обработки:

A. Ошибки авторизации:
   • Код ошибки API 53 (Authorization error) → запись в лог, уведомление менеджера: «Проверьте токен API Яндекс Директа в настройках», запрос не повторяется
   • Код ошибки 56 (Invalid parameter) → логирование параметров запроса, возврат ошибки клиенту с описанием некорректного поля
   • Код ошибки 57 (Request limit exceeded) → ожидание 60 секунд, повторный запрос (макс. 3 повтора), при превышении — уведомление менеджера

B. Сетевые ошибки:
   • getaddrinfo failed (DNS) → fallback на прямой IP api-sandbox.direct.yandex.com (для тестов) или api.direct.yandex.com (для прод), с HTTP-заголовком Host: api.direct.yandex.com
   • Connection timeout (10 сек) → повтор через 5 секунд (макс. 2 повтора)
   • Read timeout (60 сек) → отмена запроса, возврат ошибки клиенту, логирование
   • SSL error → проверка системных сертификатов, fallback на обновление CA-bundle

C. Ошибки бизнес-логики:
   • Код 3300 (Campaign not found) → проверка существования CampaignId в базе приложения, если не найден — удаление устаревшей ссылки
   • Код 3500 (AdGroup not found) → аналогично
   • Код 3600 (Ad not found) → аналогично
   • Код 3700 (Keyword already exists) → пропуск дубликата, продолжение обработки остальных ключевых слов
   • Код 3710 (Keyword invalid characters) → пропуск некорректного ключевого слова, логирование

D. Ограничение повторных попыток:
   • Максимум 3 повторных попытки для каждого метода
   • Интервал между попытками: 5 секунд → 15 секунд → 60 секунд (экспоненциальный рост)
   • После 3 неудачных попыток — запрос считается проваленным, уведомление менеджера

E. Логирование:
   • Все запросы и ответы API логируются в файл с маской: [TIMESTAMP] [METHOD] [STATUS] [Units] [ErrorCode]
   • Хранение логов: 30 дней
   • Ротация: ежедневная, архив gzip

5. УЧЁТ ТЕКУЩИХ ОГРАНИЧЕНИЙ API ДИРЕКТА

A. Ограничения на количество объектов:
   • Keywords.add: не более 50 ключевых слов за 1 вызов (реализовано ограничение на уровне приложения: batch_size = 50, при превышении — разбиение на несколько вызовов)
   • Ads.add: не более 50 объявлений за 1 вызов (приложение создаёт 1 объявление на группу, ограничение не достигается)
   • AdGroups.add: не более 50 групп за 1 вызов (приложение создаёт 1 группу на кампанию)
   • Campaigns.add: не более 10 кампаний за 1 вызов (приложение создаёт 1 кампанию)
   • Reports.add: не более 1 отчёта в очереди (приложение проверяет статус текущего отчёта перед созданием нового)

B. Ограничения на длину полей:
   • Title (ads.add): ≤33 символа — приложение обрезает автоматически с добавлением «…»
   • Title2 (ads.add): ≤30 символов — необязательное, не используется если не помещается
   • Text (ads.add): ≤75 символов — приложение обрезает до 75 символов
   • Name (campaigns.add): ≤255 символов — проверка перед отправкой
   • Keyword (keywords.add): ≤4096 символов — название товара обычно ≤100 символов, ограничение не достигается

C. Ограничения Units:
   • Заголовок Units в ответе API парсится после каждого вызова
   • При Units > 18000 (90% от лимита 20000) — приложение приостанавливает создание новых кампаний до следующего дня
   • При Units > 19000 (95% от лимита) — блокировка всех запросов кроме Campaigns.get и Keywords.get (только чтение)
   • Логирование daily units consumption

D. Стратегии и регионы:
   • Регион: только Москва (RegionIds: [1]) — жёстко задано в конфигурации
   • Стратегия поиска: HIGHEST_POSITION — автоматическое управление ставками
   • Стратегия РСЯ: NETWORK_DEFAULT — автоматическое управление
   • Не используются: аукционные стратегии, ручное управление ставками через API (кроме явного запроса менеджера)

E. Модерация:
   • После создания кампании приложение не запускает показы — запуск производит менеджер вручную через личный кабинет
   • Приложение проверяет статус модерации (Keywords.get) раз в 4 часа
   • При отклонении ключевого слова (Status = "REJECTED") — уведомление менеджера с причиной отклонения

F. Sandbox:
   • Поддерживается переключение на api-sandbox.direct.yandex.com для тестирования
   • Переключатель: переменная окружения YANDEX_DIRECT_SANDBOX=true
   • В sandbox-режиме все Campaigns.add создают кампании с бюджетом 0 и статусом «Черновик»
   • Перед первым прод-запуском обязательно выполняется тест в sandbox

G. Безопасность:
   • Все запросы через HTTPS (TLS 1.2+)
   • Токен хранится в переменной окружения (не в коде, не в Git)
   • Регулярная ротация токена (каждые 90 дней)
   • Доступ к API только с IP-адресов сервера приложения (белый список в настройках приложения, не в Яндекс OAuth)
